Built for keeping several things moving

The two things a terminal makes hard: running more than one agent at once, and knowing what any of them is doing.

Parallel tasks

Work across as many Grok Build sessions as you like from one board. Each connects to grok over ACP when you first send to it. Existing sessions are picked up from ~/.grok — nothing to import.

A readable timeline

Messages, thoughts, tool calls, shell output and plans in one stream that follows a reply as it is written — and lets go the moment you scroll up to read something further back.

Where the credits go

Weekly usage with a per-product breakdown, a 7-day token series, and live tokens and cost while a turn is running.

Paste files in

Copy anything in Finder or Explorer and paste it into the composer — it becomes a chip pointing at the file where it already lives. Screenshots too. Nothing is copied to a second place.

A rail you can keep

One line per task, grouped by project. Pin what you keep coming back to, rename anything in your own words, archive what is finished — and open any of it in a second window.

Say the next thing now

You do not have to wait for a turn to finish. Send while the agent is working and the message waits in the timeline where it will run — reorder it, edit it, drop it, or interrupt the current turn and run it immediately.

Files and Git beside it

Browse the tree, preview a file, review the agent's hunks, stage or unstage them one at a time, and commit — without leaving the task.

Two steps, both platforms

ZtidalCode never handles your credentials — it reuses the session grok login creates.

Install Grok Build

Needs SuperGrok, X Premium+, or SuperGrok Heavy. Then grok login once.

macOS

curl -fsSL https://x.ai/cli/install.sh | bash

Windows PowerShell

irm https://x.ai/cli/install.ps1 | iex
2A

Install on macOS

On an Apple Silicon Mac, take the .dmg, open it and drag ZtidalCode into Applications. See the Gatekeeper note below for the first launch. 

ZtidalCode_<version>_aarch64.dmg
2B

Install on Windows

On 64-bit Windows, take the setup.exe. It installs per-user with no administrator and updates itself. Keep the MSI for administrator-managed, per-machine deployment. 

ZtidalCode_<version>_x64-setup.exe

A few things to know first

OS warnings and updater signatures solve different problems. Both are easier to hear about now than to discover later.

Gatekeeper: right-click Open once

The Mac build is not Apple Developer ID signed or notarized, so Gatekeeper may block a normal first double-click. In Finder, right-click ZtidalCode, choose Open, then confirm Open once. Later launches work normally.

SmartScreen will warn you

The Windows installers are not Authenticode-signed, so the system reports an unknown publisher. Check the download against SHA256SUMS.txt on the release before continuing.

In-app updates verify themselves

Update payloads on macOS and Windows carry minisign signatures and are checked against a public key compiled into the app. This is independent of Gatekeeper and SmartScreen: those updater payloads cannot be substituted without detection.

The agent cannot see images

grok does not accept images over the protocol. Attach a picture and it writes code to inspect it instead, which it is good at — so "read these files" works properly, while "what does this screenshot say" does not.
